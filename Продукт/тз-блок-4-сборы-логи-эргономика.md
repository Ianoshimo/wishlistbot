# ТЗ блок 4: сборы на некупленные подарки, складчина до 100, логи, эргономика

Дата: 2026-10-07. Источник: обратная связь владельца продукта после живого
теста в Telegram (скриншот iPhone, мини-апп в полноэкранном режиме).

## Контекст и ограничения

- Платформа не принимает и не хранит деньги: ЮKassa, ИП и эскроу отложены
  до итерации 2 (CLAUDE.md, решение 2026-10-01). Любая механика денег в
  этом блоке - только перевод напрямую между людьми, вне платформы.
- У банков уже есть бесплатный встроенный "сбор денег" со ссылкой (Т-Банк,
  Сбер, Альфа, ВТБ, Озон Банк и др.). Ценность для нас - не перевод, а
  данные: кто, на что, к какому поводу собирает.

## 1. Скинуться на ещё не купленный подарок (айфон за 120 000 ₽)

**Проблема.** "Скинуться" работает только для "уже купил(а) сам(а)": деньги
идут на номер телефона получателя. На дорогую вещь, которую никто ещё не
купил, скинуться нельзя.

**Решение - "сбор по ссылке банка".** Получатель (или любой организатор) заранее
создаёт сбор в приложении своего банка и вставляет ссылку на него в позицию.
Друзья скидываются через банк, в приложении отмечают участие.

Требования:
1. У позиции новое необязательное поле `fundraiserUrl` - ссылка http(s) на
   сбор в банке (валидация как у ссылки на товар, Б-8).
2. Режим "Можно скинуться нескольким" (`maxContributors` 2-100) доступен,
   если у позиции есть **либо** `selfPurchased` + номер СБП (как сейчас),
   **либо** `fundraiserUrl`. Без одного из двух - 400 `validation_error`.
3. Форма добавления: чекбокс "Можно скинуться нескольким" доступен всегда.
   Если "Уже купил(а) сам(а)" не отмечено - при включённой складчине
   обязательно поле "Ссылка на сбор в банке" с подсказкой, как его создать.
4. Подсказка для дорогих подарков: если цена не меньше 5 000 ₽ и подарок не
   "уже купил сам", форма предлагает "Дорогой подарок? Создайте сбор в
   приложении банка и вставьте ссылку - друзья смогут скинуться".
5. Экран дарителя для позиции со сбором: кнопка "Скинуться через сбор"
   (присоединяет к позиции и открывает ссылку банка), рекомендуемая сумма
   = цена / число участников, кнопка "Я скинулся" (самоотметка).
   Номер телефона получателя в этом режиме не показывается и не нужен.
6. Позиция становится "Куплено" (по смыслу - "собрано"), когда отметились
   все участники, как в текущей складчине. Срок 5 дней на долю - как сейчас.
7. Карточка в списке: "Сбор · участвуют X из Y" вместо "перевод по СБП".

## 2. Складчина до 100 участников

**Проблема.** Лимит 10 (`MAX_CONTRIBUTORS_CAP`).
**Решение.** Лимит 100 на бэкенде и во всех формах (2-100).

## 3. Изменение числа участников при редактировании

**Проблема.** `maxContributors` задаётся только при создании.

Требования (PATCH `/api/items/:itemId`, форма "Редактировать позицию"):
1. Можно менять `maxContributors` (1-100) и `fundraiserUrl`. Только владелец.
2. Нельзя поставить меньше, чем уже присоединилось участников - 409
   `contributors_below_joined` с понятным текстом ("Уже участвуют N -
   меньше поставить нельзя").
3. Включить складчину (1 → больше 1) можно, только если позицию никто не
   забронировал обычной бронью, и есть номер СБП или ссылка на сбор.
4. Выключить (больше 1 → 1) можно, только если нет ни одного участника.
5. Если после уменьшения все участники уже отметились и их ровно столько,
   сколько мест, - позиция становится "Куплено" и получатель получает
   уведомление (как при последней оплате).

## 4. Логи и статистика "всего и вся"

Требования:
1. Серверные события (таблица `Event`, без персональных данных, как сейчас)
   дополнительно на: редактирование позиции (имена изменённых полей),
   удаление позиции, переключение приоритета, переименование вишлиста,
   изменение настроек складчины, ошибки API 5xx (`api_error`: маршрут,
   метод, код).
2. Клиентские события: `POST /api/events` - только для авторизованного
   пользователя (initData), белый список типов, не больше 20 полей в props,
   только строки/числа/булевы, строки до 100 символов, лимит 120 событий в
   минуту на пользователя (сверх - молча отбрасываем). Типы: открытие
   приложения (платформа, версия Telegram, тип стартового параметра, тема,
   полноэкранный режим), просмотр экрана, копирование ссылки "Поделиться",
   переход в магазин, переход по ссылке сбора, копирование реквизитов СБП,
   "В календарь", подписка на календарь, открытие форм, показанная
   пользователю ошибка.
3. Ошибка записи события никогда не ломает основной запрос и интерфейс.
4. Отчёт `npm run analytics:report` дополняется: активные пользователи по
   дням (DAU) и за период, события по дням, топ экранов, клиентские
   события, доля открытий в полноэкранном режиме, ошибки API.

## 5. Эргономика: кнопки под пальцем, ничего под системными кнопками Telegram

**Проблема (скриншот).** В полноэкранном режиме Telegram поверх мини-аппа
рисует "Закрыть" и "⌄ •••" - под ними оказались заголовок, кнопки
"Календарь" и "Поделиться", кнопка "Назад". Верх и низ экрана неудобны
для большого пальца.

Требования:
1. Учитывать безопасные отступы Telegram (`--tg-safe-area-inset-*`,
   `--tg-content-safe-area-inset-*`, Bot API 8.0) и `env(safe-area-inset-*)`
   сверху и снизу на всех экранах, в нижних шторках и у плавающей "+".
2. Кнопки "Поделиться" и "Повод/календарь" переезжают из правого верхнего
   угла в ряд крупных кнопок под карточкой прогресса (зона большого пальца).
3. Внутри Telegram кнопка "Назад" - нативная Telegram BackButton, а не
   стрелка в левом верхнем углу (её место занимает "Закрыть").
4. Плавающая "+" и нижние кнопки экрана позиции - выше нижнего безопасного
   отступа.

## Критерии приёмки
- Сборка бэкенда/фронтенда чистая, юнит-тесты проходят.
- API: создание позиции со сбором без "уже купил", 2-100 участников, 101 →
  400, редактирование числа участников по правилам п.3 (включая 409),
  события пишутся, `/api/events` отвергает неизвестные типы и чужие поля.
- UI на 390px: шапка без кнопок справа, ряд "Поделиться/Повод" под
  прогрессом, отступы сверху/снизу заданы через переменные Telegram.
