# ТЗ: редактирование всех полей позиции

Дата: 2026-10-07. Источник: решение владельца продукта по пункту 3
"Следующего шага" CLAUDE.md ("менять ли 'Уже купил(а) сам(а)' у
существующей позиции") - **"Да, редактировать можно всё"**.

## Контекст

Сейчас в шторке "Редактировать позицию" (`EditItemForm.tsx`,
`PATCH /api/items/:itemId`) меняются ссылка, название, цена, число
участников складчины и ссылка на сбор. Флаг "Уже купил(а) сам(а)"
(`Item.selfPurchased`) и номер СБП задаются только при создании, фото
подтягивается только при создании - после правки ссылки на другой товар
остаётся фото старого.

Сверка форм поле за полем:

| Поле | Создание (`AddItemForm`) | Правка до | Правка после |
|---|---|---|---|
| Ссылка на товар | да | да | да |
| Название | да | да | да |
| Цена | да | да | да |
| Фото | авто по ссылке | нет | "Обновить фото по ссылке" (авто, как при создании) |
| "Уже купил(а) сам(а)" | да | нет | да |
| Номер СБП | да (при "купил сам") | нет | да (при "купил сам") |
| "Можно скинуться нескольким" + число мест | да | только число | да (тоггл + число, как при создании) |
| Ссылка на сбор | да | да | да |
| "Хочу больше всего" (приоритет) | нет (звёздочка в списке) | нет | да (дублирует звёздочку) |

Фото вручную (свой файл/ссылка на картинку) при создании не задаётся - в
правку тоже не добавляем.

## Что редактируется

1. **Косметика** - ссылка, название, цена, фото, приоритет. Разрешена
   всегда, в любом статусе (в т.ч. "куплено").
2. **Режим подарка** - "уже купил сам" (вкл/выкл), складчина (вкл/выкл,
   число мест), ссылка на сбор. Ограничен правилами ниже.
3. **Номер СБП** - реквизит владельца (`User.sbpPhone`), а не позиции. Как
   и при создании: присланный номер сохраняется в профиль и действует для
   всех его позиций "уже купил сам". Даритель, который уже забронировал,
   при следующем открытии подарка увидит новый номер - это и нужно
   получателю (номер сменился - деньги должны прийти на новый).

## Правила режима

Принцип: **нельзя молча сломать обязательство уже присоединившегося
дарителя.** Даритель бронирует под конкретный способ подарить (купить в
магазине / перевести по СБП / скинуться через сбор банка) и мог уже
действовать - купить в магазине или перевести деньги, ещё не отметив это
в приложении. Поэтому способ подарить меняется только пока никто не
присоединился.

"Есть участники" = classic-бронь (`reservedByUserId`, статус `reserved`)
или хотя бы одна живая доля складчины (`GiftShare`). Просроченные брони и
неоплаченные доли (TTL 5 дней) снимаются до проверки, как и везде.

| Состояние позиции | Косметика | "Уже купил сам" вкл/выкл | Складчина вкл/выкл, число мест | Ссылка на сбор |
|---|---|---|---|---|
| Свободна, участников нет | да | да | да | да |
| Забронирована (classic) | да | 409 `item_has_givers` | вкл - 409 `split_item_already_reserved` (как было) | не применимо |
| Складчина, есть доли | да | 409 `item_has_givers` | число мест - не меньше участников; выкл - 409 `contributors_below_joined` (как было) | менять можно (ТЗ блок 4 п.3), убрать - только если есть СБП |
| Куплена | да | 409 `item_already_bought` | 409 `item_already_bought` | 409 `item_already_bought` |

Почему так:
- "Уже купил сам" при брони: включили - даритель, уже купивший подарок в
  магазине, вдруг видит "переведите деньги"; выключили - даритель, уже
  переведший по СБП, видит "купите в магазине" и теряет номер. Оба
  варианта ломают обещание. Владелец видит статус "Забронировано" в
  списке, поэтому отказ не раскрывает ничего нового (личность дарителя
  по-прежнему скрыта, п.2 спеки).
- Куплено - сделка закрыта, менять способ дарения уже нечего (расширение
  QB4-4 со складчины на все поля режима).
- Ссылку на сбор при участниках менять можно - это уже было разрешено
  блоком 4 (банк пересоздал сбор), убрать нельзя без СБП - дарителям
  некуда будет переводить.

Отказ - только по реальному изменению: если поле прислано с тем же
значением, что уже стоит, это не "смена режима" (фронт и так шлёт только
изменённое, но бэкенд не полагается на это).

## Инварианты (QB4-3), проверяются после применения правки

1. Ссылка на сбор живёт только у складчины **без** "уже купил сам". При
   выключении складчины или включении "уже купил сам" ссылка молча
   очищается (как при создании и в QB4-3). То же правило добавляется в
   создание: `selfPurchased` + `fundraiserUrl` - ссылка отбрасывается.
2. Складчина (`maxContributors > 1`) требует "уже купил сам" или ссылку
   на сбор - иначе 400 `split_needs_payment_target`.
3. Включение "уже купил сам" требует номер: присланный в запросе или уже
   сохранённый у владельца - иначе 400 `sbp_phone_required`. Формат номера
   - тот же, что при создании (`PHONE_RE`), иначе 400 `validation_error`.

## Фото по ссылке

- В форме, когда ссылка изменена, появляется галочка "Обновить фото и
  название по новой ссылке" (по умолчанию включена). Бэкенд (`refreshPreview:
  true`) подтягивает превью той же логикой, что и создание (свой парсинг +
  Apify-фоллбэк для Wildberries).
- Фото: нашлось - заменяем; не нашлось - убираем старое (оно от другого
  товара и вводило бы дарителя в заблуждение).
- Название: подставляется из превью, **только если** владелец не поменял
  название вручную в той же правке.
- Подгрузка может идти до ~30 с - под кнопкой та же подсказка, что при
  создании.

## Приватность

- Ответ PATCH и ошибки не содержат номер СБП (номер видит только держатель
  брони/доли - hotfix Н-1); сериализация через `serializeItemView` с
  `viewerUserId = null`, как и раньше.
- Правит только владелец (403 `not_your_wishlist` до любых проверок
  режима - посторонний не узнаёт даже статус).
- Аналитика - без персональных данных (см. ниже).

## Аналитика

- `item_edited` - расширяется: `fields` (имена изменённых полей; `sbpPhone`
  - только как имя поля, без значения), `status`, `mode`
  (`classic`/`split` после правки), `selfPurchased` (после правки),
  `contributors` (сколько уже участвует), `previewRefreshed`.
- Новое `item_edit_blocked` - отказ по правилам режима: `reason` (код
  ошибки), `status`, `mode`, `contributors`. Нужно, чтобы понять, как часто
  владельцы упираются в блокировку и не стоит ли дать "отменить бронь".
- `split_settings_changed` - как было.

## UI (`EditItemForm`)

- Повторяет форму создания: галочки "Уже купил(а) сам(а)" и "Можно
  скинуться нескольким" с теми же подписями, номер СБП (подставляется из
  профиля), число мест (2-100), ссылка на сбор, плюс "Хочу больше всего".
- Поля режима, которые менять нельзя, не прячутся, а показываются
  неактивными с пояснением одной строкой: "Подарок уже забронирован -
  способ подарить не меняется" / "Подарок уже куплен - менять можно только
  ссылку, название, цену и фото".
- Ошибки - над кнопкой "Сохранить" (QB4-2), коды ошибок - машинные (QB4-5).

## Критерии приёмки

1. Свободная позиция: "уже купил сам" вкл (с сохранённым номером и с
   новым), выкл - 200; без номера ни в запросе, ни в профиле - 400
   `sbp_phone_required`.
2. Classic-бронь: смена "уже купил сам" - 409 `item_has_givers`;
   название/цена/ссылка - 200.
3. Складчина с долей: смена "уже купил сам" - 409 `item_has_givers`;
   число мест не меньше участников - 200; смена ссылки на сбор - 200.
4. Куплено: любое поле режима - 409 `item_already_bought`; косметика - 200.
5. Включение "уже купил сам" у складчины со сбором очищает ссылку; выключение
   "уже купил сам" у складчины без ссылки - 400 `split_needs_payment_target`.
6. Номер СБП не появляется в ответе PATCH и не виден постороннему зрителю
   (GET без брони) после правки; даритель с бронью видит номер.
7. Смена ссылки с "Обновить фото" - фото заменено (или убрано, если не
   нашлось); без галочки - фото прежнее.
8. Чужой telegramId - 403 до любых проверок режима.
9. `item_edited`/`item_edit_blocked` в БД - без номера, имён, telegramId.
10. Форма на 390px: все поля доступны, ошибки видны у кнопки, заблокированные
    поля показаны с пояснением.

## Вне скоупа

- Отмена брони владельцем (чтобы разблокировать смену режима) - отдельное
  продуктовое решение, данные из `item_edit_blocked` помогут его принять.
- Ручная загрузка своего фото.
- Уведомление дарителю об изменении позиции.
