# Задачи: итерация 2 - деньги и календарь (черновик)

Перенесено из задач итерации 1 при сужении её скоупа 2026-09-29. Код по
всем пунктам ниже уже написан (см. корневой `README.md`) - это не бэклог
"что написать с нуля", а список того, что нужно довести до реального
подключения (закрыть открытые вопросы спеки, подключить настоящий приём
денег вместо заглушки, донастроить приватность календаря).

## Бэкенд

**Б4. Интеграция с ЮKassa - приём СБП.** Приём платежей по сбору,
объединение N платежей одного сбора в пул на своей стороне (агрегатор видит
независимые платежи), явные статусы сбора - открыт/собран/истёк. Сейчас
эндпоинт `/api/pools/:id/contribute` только фиксирует намерение (статус
pending), реального списания нет - см. `спека-итерация-2-черновик.md`.
Связано с Ф3, Ф4.

**Б5. Автовозврат при истёкшем сборе.** Полный автоматический возврат всем
дарителям через API ЮKassa при истечении срока без набора суммы, без
частичных вариантов и без ручного решения организатора. Продление срока
организатором до истечения (уже работает в коде). Связано с Ф3, Ф5.

**Б7. Генерация ICS/webcal-фида.** Один фид на пользователя со всеми его
сборами (и как организатора, и как дарителя) и датами поводов из
вишлистов, куда он вовлечён. Минимальная версия уже в коде
(`backend/src/routes/calendar.ts`), без разделения по ролям и без решения
по приватности - см. открытый вопрос в `спека-итерация-2-черновик.md`.

## Фронтенд (Telegram Mini App)

**Ф3. Создание сбора (организатор).** Форма - повод, дата повода
(необязательно), целевая сумма (необязательно), срок. Уже реализовано
(`frontend/src/pages/PoolCreate.tsx`), не подключено к экранам итерации 1.

**Ф4. Экран сбора (в процессе).** Прогресс-бар, сумма/цель, список взносов
без указания личности плательщика, роль организатор/даритель. Уже
реализовано (`PoolProgress.tsx`).

**Ф5. Экран истёкшего сбора.** Статус "истёк", список возвратов, без
указания личности. Сейчас это состояние внутри `PoolProgress.tsx`, отдельный
артборд макета `PoolExpired` с ним не сведён 1:1 - свести при следующей
работе над экраном.

**Ф8 (продолжение). Экран расшаривания сбора.** По макету - артборд
`SharePool`. Сейчас в коде это заглушка (`frontend/src/pages/SharePool.tsx`).

**Ф10. Взнос в сбор (даритель).** Ввод суммы, отправка - есть
(`Contribute.tsx`), но честно показывает, что оплата не подключена, вместо
фейковых состояний успех/ошибка из макета. Довести до реального ЮKassa
после Б4.

**Ф11. Роль в экране сбора.** Реализовано в `PoolProgress.tsx` через
`viewerIsOrganizer` с бэкенда.

**Ф13 (продолжение). Приглашение по ссылке на сбор.** По макету - артборд
`InvitePool`. В коде пока не заведено (только приглашение на вишлист
реализовано в `SharedWishlist.tsx`).

**Ф14. Экран "Календарь" (получатель).** Месячный вид с отметками дней,
список ближайших событий. По макету - артборд `Calendar`. В коде -
заглушка (`CalendarRecipient.tsx`).

**Ф15. Дата повода в создании сбора.** Реализовано в `PoolCreate.tsx`.

**Ф16. Календарь дарителя.** По макету - артборд `CalendarGiver`. В коде -
заглушка (`CalendarGiver.tsx`).

**Ф17. Календарь организатора.** По макету - артборд `CalendarOrganizer`.
В коде - заглушка (`CalendarOrganizer.tsx`), доступна из шапки
`PoolProgress` в режиме организатора.
